# Agentic Project Builder

A lean Hermes team demo that turns a high-level software goal into a working artifact through the existing Kanban task graph:

User goal → Odin plans → Bao researches → Brokkr implements → Veritas independently reviews → Human approves release.

The demo artifact is a zero-framework ETF comparison web app backed by committed fixture data. Python is the primary implementation and the only development/runtime toolchain. The browser retains one small JavaScript adapter for loading Python-generated display data, DOM rendering, and selection events.

## Demo behavior

- Choose two distinct ETFs from committed fixtures.
- Compare ticker/name, issuer, expense ratio, AUM, inception date, benchmark/category, holdings/sector exposure, and a dated performance snapshot.
- Read a deterministic explanation of material differences.
- See source links, field-level as-of dates, and a non-advice/data-freshness disclaimer.
- Same or invalid selections are reported instead of compared.
- No backend, database, authentication, secrets, live data calls, Pyodide, or deployment is included.

## Setup and local use

Requirement: Python 3.11+. Node.js is not required.

From the repository root on macOS, Linux, or another POSIX shell:

    PYTHONPATH=src python -m agentic_project_builder validate-fixtures
    PYTHONPATH=src python -m unittest discover -s tests_python -v
    PYTHONPATH=src python -m agentic_project_builder serve

On Windows PowerShell:

    $env:PYTHONPATH = "src"
    python -m agentic_project_builder validate-fixtures
    python -m unittest discover -s tests_python -v
    python -m agentic_project_builder serve

Open `http://localhost:4173`.

Use a different port with:

    PYTHONPATH=src python -m agentic_project_builder serve --port 5000

or:

    PORT=5000 PYTHONPATH=src python -m agentic_project_builder serve

With the server running, execute the live Chrome smoke test in another terminal:

    PYTHONPATH=src python -m agentic_project_builder check-browser

Or in another Windows PowerShell terminal:

    $env:PYTHONPATH = "src"
    python -m agentic_project_builder check-browser

The smoke test checks initial rendering, invalid same-fund selection, an alternate valid comparison, reload behavior, browser exceptions/warnings, failed requests, and HTTP 4xx/5xx responses. `CHROME_PATH`, `URL`, and `CDP_PORT` can override its defaults.

The package can also be installed and run through its console script:

    python -m pip install .
    agentic-project-builder validate-fixtures
    agentic-project-builder serve

## Architecture

Python owns the data models, fixture loading, validation, comparison rules, formatting, explanation generation, static browser-data generation, CLI, static server, tests, and browser smoke test.

`browser-data.json` is a committed static projection generated by Python. It contains every fixture-backed selection result plus sources and metadata. The browser does not reimplement domain rules: `src/main.js` only fetches that projection, maps selections to precomputed results, renders DOM nodes, and handles change events.

The repository and packaged static assets are intentionally duplicated so an installed wheel can serve without repository-relative paths. Python tests enforce byte-for-byte synchronization for `index.html`, `browser-data.json`, `src/main.js`, and `src/styles.css`. `build-browser-data` refreshes both generated JSON copies in a source checkout.

## Project layout

- `src/agentic_project_builder/` — Python implementation, CLI, static server, and browser checker
- `src/agentic_project_builder/site/` — packaged static site
- `fixtures/etfs.json` and `src/agentic_project_builder/site/fixtures/etfs.json` — repository and packaged fixture copies
- `browser-data.json` — repository copy of Python-generated browser display data
- `index.html`, `src/main.js`, `src/styles.css` — repository static assets; JavaScript is DOM/events only
- `tests_python/` — Python unit, CLI, server, asset-synchronization, and browser-check tests
- `pyproject.toml` — Python package and console-script metadata; no runtime dependencies
- `docs/fixture-schema.md` — fixture contract and refresh procedure
- `docs/workflow-note.md` — workflow and architecture evidence

## Fixture refresh checklist

1. Update both fixture copies from issuer/SEC sources.
2. Run `PYTHONPATH=src python -m agentic_project_builder validate-fixtures`.
3. Run `PYTHONPATH=src python -m agentic_project_builder build-browser-data`.
4. Run `PYTHONPATH=src python -m unittest discover -s tests_python -v`.
5. Start the Python server and run `PYTHONPATH=src python -m agentic_project_builder check-browser`.
6. Do not publish or deploy until Veritas passes and a human explicitly approves release.

## Data and disclaimer
